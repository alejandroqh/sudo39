## What this is

sudo39 is a Rust MCP (Model Context Protocol) server built with TurboMCP that exposes a guarded OS privilege-elevation tool (`sudo_run`). It lets MCP clients run commands via `sudo`, `pkexec`, `osascript`, or PowerShell UAC, gated by an allowlist policy and confirmation-phrase workflow.

## Build and test commands

```sh
cargo build                # debug build
cargo build --release      # release build
cargo test                 # run all tests
cargo test <test_name>     # run a single test (e.g. cargo test normalizes_program)
cargo clippy               # lint
cargo fmt -- --check       # check formatting
```

Rust edition is 2024. Dependencies: `tokio` (async runtime) and `turbomcp` (MCP framework).

## Architecture

The entire server lives in `src/main.rs` (~667 lines, single-file crate). Key sections:

- **`Sudo39` struct + `#[server]` impl** (lines 13–184): The TurboMCP server definition. Contains all MCP tools (`sudo_run`, `sudo39_policy`, `sudo39_add_allowed_program`, `sudo39_remove_allowed_program`, `sudo39_set_allow_unsafe`, `sudo39_reload_policy_from_env`) and MCP prompts (`confirm_*`). The `#[tool]` and `#[prompt]` attributes are TurboMCP macros.

- **`Policy`** (lines 186–217): Runtime allowlist loaded from `SUDO39_ALLOWED_PROGRAMS` and `SUDO39_ALLOW_UNSAFE` env vars. Wrapped in `Arc<RwLock<>>` for concurrent access. In-memory only — mutations don't persist across restarts.

- **`ElevationMode` + platform runners** (lines 323–466): Per-platform elevation dispatch. `auto` picks the OS-native method. Each mode has a real implementation gated by `#[cfg(target_os = ...)]` and a stub returning an error on unsupported platforms.

- **`run_command`** (lines 492–546): Spawns the elevation launcher, reads stdout/stderr on background threads with size limits (`SUDO39_OUTPUT_LIMIT_BYTES`), and enforces a timeout (`SUDO39_TIMEOUT_SECS`) via polling.

- **Confirmation system** (lines 287–315): Every mutating admin tool requires an exact confirmation phrase. Phrases are generated by `confirm_*_phrase` functions and verified by `require_confirmation`.

- **Audit logging** (lines 595–620): All executions and policy changes emit structured events to stderr.

## Key design constraints

- No password parameter by design — credentials must never flow through MCP context. Elevation relies on host-configured mechanisms (`SUDO39_ASKPASS`, macOS admin prompt, Windows UAC).
- Commands execute without a shell on Linux/Windows. macOS `osascript` path shell-quotes the argument vector into AppleScript.
- stdin/stdout are the MCP transport, so `sudo` runs with `-n` (non-interactive) unless an askpass helper is configured.
- The `command` field must be a single program path (no whitespace); arguments go in the `arguments` array.

## Environment variables

| Variable | Default | Purpose |
|---|---|---|
| `SUDO39_ALLOWED_PROGRAMS` | (empty) | Comma-separated allowlist |
| `SUDO39_ALLOW_UNSAFE` | (unset) | Set to `1` to allow any program |
| `SUDO39_TIMEOUT_SECS` | 30 | Per-execution timeout |
| `SUDO39_OUTPUT_LIMIT_BYTES` | 4096 | Max bytes captured per stream (~1000 LLM tokens) |
| `SUDO39_ASKPASS` | (unset) | Path to askpass helper for `sudo -A` |
